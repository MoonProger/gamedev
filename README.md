# Gamedev — многопользовательская образовательная настольная игра

## О проекте

**Gamedev** — это командный учебный проект, представляющий собой веб-версию многопользовательской настольной игры. Проект объединяет в себе элементы образовательной игры, симулятора развития персонажа и соревновательной онлайн-игры.

Игроки попадают на игровое поле, выбирают персонажа, развивают разные сферы навыков, получают карточки событий, выполняют проекты и соревнуются друг с другом. Игра рассчитана как на несколько реальных игроков, так и на игру с ботами, что позволяет запускать матч даже при отсутствии второго участника.

Проект был разработан в рамках курсовой работы и демонстрирует полный цикл создания интерактивного веб-приложения: от проектирования базы данных и серверной логики до визуального игрового интерфейса и real-time взаимодействия между игроками.

---

## Идея проекта

В основе проекта лежит идея создания настольной игры о развитии человека в разных сферах. Игрок не просто перемещается по полю, а постепенно прокачивает навыки, сталкивается с игровыми ситуациями и принимает решения.

Игровые сферы включают:

* IT;
* бизнес;
* медиа;
* спорт;
* туризм;
* науку;
* искусство;
* волонтёрство;
* финансы;
* опыт;
* успех.

Каждая клетка поля и каждая карточка влияют на развитие игрока. За счёт этого игра становится не только соревновательной, но и образовательной: она моделирует процесс накопления опыта, развития компетенций и движения к цели.

## Цель проекта

Цель проекта — разработать полноценную многопользовательскую браузерную игру с серверной логикой, базой данных, авторизацией, комнатами, WebSocket-синхронизацией и визуальной частью на Unity WebGL.

В рамках проекта команда решала несколько важных задач:

1. Создать удобный веб-интерфейс для пользователей.
2. Реализовать регистрацию и авторизацию.
3. Разработать систему игровых комнат.
4. Реализовать real-time взаимодействие между игроками.
5. Интегрировать Unity WebGL в React-приложение.
6. Реализовать серверную игровую механику.
7. Добавить поддержку ботов.
8. Обеспечить возможность игры как с реальными игроками, так и с ботами.
9. Подготовить проект к демонстрации и дальнейшему развитию.

## Основной пользовательский сценарий

Пользователь проходит следующий путь:

1. Заходит на сайт.
2. Регистрируется или входит в аккаунт.
3. Создаёт игровую комнату.
4. Приглашает другого игрока или добавляет бота.
5. Отмечает готовность.
6. Запускает игру.
7. Выбирает персонажа.
8. Бросает кубик.
9. Перемещается по игровому полю.
10. Получает карточки и игровые события.
11. Прокачивает сферы персонажа.
12. Соревнуется за победу.

Проект поддерживает два основных сценария игры:

* несколько реальных игроков;
* один реальный игрок и один или несколько ботов.

## Что реализовано

### 1. Регистрация и авторизация

В проекте реализована система пользователей. Пользователь может зарегистрироваться, войти в аккаунт и выполнять игровые действия под своей учётной записью.

Реализовано:

* регистрация по email, username и паролю;
* вход в систему;
* JWT-авторизация;
* получение данных текущего пользователя;
* защита серверных маршрутов.

---

### 2. Система комнат

Перед началом игры пользователи попадают в систему комнат. Один пользователь создаёт комнату, остальные могут подключиться к ней.

Реализовано:

* создание комнаты;
* список комнат;
* подключение к комнате;
* выход из комнаты;
* приватные комнаты;
* готовность игроков;
* запуск игры создателем комнаты;
* закрытие комнаты;
* удаление комнаты;
* ограничение количества игроков.

Комната выступает как лобби перед началом матча.

---

### 3. Игровой процесс

После старта игры сервер создаёт игровое состояние. Игроки выбирают персонажей, после чего начинается пошаговый игровой процесс.

Игровой ход состоит из нескольких этапов:

1. Ожидание броска кубика.
2. Бросок кубика.
3. Выбор доступной клетки.
4. Перемещение игрока.
5. Выполнение действия на клетке.
6. Передача хода следующему игроку.

Сервер контролирует корректность действий, хранит состояние игры и рассылает обновления всем участникам.

---

### 4. Выбор персонажей

Перед началом матча игрок выбирает персонажа. Персонаж влияет на начальные характеристики и дальнейший игровой процесс.

Для обычных игроков выбор происходит вручную через интерфейс игры.

Для ботов выбор персонажа происходит автоматически. Это позволяет запускать игру с ботами без дополнительных действий со стороны пользователя.

---

### 5. Игровое поле

Визуальная часть игрового поля реализована через Unity WebGL и встроена в React-приложение.

Игровое поле отображает:

* игроков;
* клетки;
* движение по полю;
* состояние хода;
* карточки;
* игровые события;
* параметры персонажа.

Frontend получает состояние игры от сервера и передаёт его в Unity. Unity отображает это состояние пользователю.

---

### 6. Карточки и события

Во время игры пользователь попадает на разные клетки и получает карточки. Карточки изменяют характеристики игрока и создают игровые ситуации.

Карточки могут влиять на:

* деньги;
* опыт;
* успех;
* IT;
* бизнес;
* спорт;
* медиа;
* туризм;
* науку;
* искусство;
* волонтёрство.

Таким образом игра становится динамичной: каждый ход может изменить стратегию игрока.

---

### 7. Проекты

В игре предусмотрены проектные клетки. Они связаны с развитием сфер и накоплением ресурсов. Игрок может принимать решения, связанные с проектами, и за счёт этого продвигаться к победе.

Проекты добавляют игре стратегический элемент: игроку важно не только двигаться по полю, но и развивать нужные характеристики.

---

### 8. Боты

Одним из важных улучшений проекта стала реализация ботов.

Боты нужны для того, чтобы игру можно было запускать даже в том случае, если рядом нет второго реального игрока. Это делает проект более удобным для демонстрации и тестирования.

Реализовано:

* добавление бота в комнату;
* удаление бота из комнаты до старта игры;
* отображение бота в списке игроков;
* автоматическая готовность бота;
* автоматический выбор персонажа ботом;
* автоматический бросок кубика;
* автоматический ход по полю;
* автоматическое выполнение действия на клетке;
* корректная работа сценария «один игрок + бот».

Бот является полноценным участником комнаты и игрового процесса, но не требует отдельного браузера или WebSocket-подключения.

---

## Почему боты важны для проекта

Добавление ботов решило сразу несколько задач:

1. Упростило демонстрацию проекта.
2. Позволило запускать игру одному пользователю.
3. Упростило тестирование игровой логики.
4. Сделало проект более завершённым.
5. Позволило показать работу автоматизированных игровых действий.

Без ботов для демонстрации требовалось минимум два реальных пользователя. После добавления ботов преподаватель или участник команды может самостоятельно создать комнату, добавить бота и пройти игровой сценарий.

## Основные модули backend

### Auth

Модуль авторизации отвечает за регистрацию, вход и проверку пользователя.

### Rooms

Модуль комнат отвечает за создание комнат, подключение игроков, готовность, выход, закрытие и удаление комнат.

### Game

Модуль игры содержит основную игровую механику: старт игры, выбор персонажей, ходы, кубик, карточки, проекты, таймеры и ботов.

### WebSocket

Модуль WebSocket обеспечивает real-time обмен между сервером и клиентами.

### Stats

Модуль статистики отвечает за сохранение и получение результатов игроков.

### Users

Модуль пользователей отвечает за данные профиля и аватары.

## Основные состояния игры

Игра использует несколько ключевых фаз:

```text
CHARACTER_SELECTION
WAITING_ROLL
WAITING_MOVE
WAITING_ACTION
```

### CHARACTER_SELECTION

Фаза выбора персонажей. Игрок выбирает персонажа вручную, бот получает персонажа автоматически.

### WAITING_ROLL

Фаза ожидания броска кубика.

### WAITING_MOVE

Фаза ожидания перемещения по полю после броска кубика.

### WAITING_ACTION

Фаза ожидания действия на клетке.

## Как запустить проект

### 1. Клонировать репозиторий

```bash
git clone https://github.com/MoonProger/gamedev.git
cd gamedev
```

---

### 2. Запустить backend

```bash
cd server
npm install
npx prisma migrate dev
npx prisma generate
npm run dev
```

Backend запускается на:

```text
http://localhost:4000
```

Проверка:

```bash
curl http://localhost:4000/health
```

---

### 3. Запустить frontend

Во втором терминале:

```bash
cd web
npm install
npm run dev
```

Frontend запускается на:

```text
http://localhost:5173
```

## Что было самым сложным

Одной из самых сложных частей проекта была синхронизация состояния между backend, frontend и Unity.

Сервер хранит игровое состояние и отправляет его клиенту. Frontend должен правильно преобразовать это состояние и передать его в Unity. Unity, в свою очередь, должна корректно отобразить состояние игры и отправить действия пользователя обратно на сервер.

Особенно важной стала реализация сценария с ботами. При игре с двумя реальными игроками оба участника выбирают персонажей вручную. При игре с ботом бот выбирает персонажа автоматически. Из-за этого потребовалось аккуратно согласовать серверное состояние и экран выбора персонажа, чтобы живой игрок всё равно видел экран выбора, а бот не мешал началу матча.
